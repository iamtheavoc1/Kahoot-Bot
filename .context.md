# Kahoot-Bot (fork)

Fork of `Jones8683/Kahoot-Bot` adding correct answer resolution and a spam layer.

## What this directory is

- `index.js` -- terminal interface only: screen, input, rendering. All command
  behaviour lives in `lib/commands.js` so it can be tested without a TTY.
- `capture.js` -- live diagnostic. Dumps raw packets and probes the questions
  that only a live game can answer. Run it against a real game.
- `lib/` -- the parts with real logic:
  - `question.js` -- raw `questionStart` payload -> plain question and options.
    Field names are documented in `docs/PROTOCOL.md`.
  - `resolver.js` -- OpenAI-compatible `/chat/completions` client, plus the
    text matching that maps a model reply back onto an option.
  - `answer-cache.js` -- one resolver call per question, shared by every bot.
  - `names.js` -- bot names, the 15 character limit, and the zero-width
    character workaround for Kahoot's name filter.
  - `bots.js` -- bot lifecycle, the answering modes, the spam layer.
  - `commands.js` -- command parsing and dispatch.
  - `config.js` -- environment defaults and PIN parsing.
- `test/` -- `run.js` is the runner. `unit.js` covers the pure functions,
  `commands.js` covers every command, `integration.js` and `scale.js` drive a
  real Kahoot challenge. `fixtures.js` holds captured payloads.
- `docs/PROTOCOL.md` -- the verified protocol reference. Read this before
  changing anything that touches the Kahoot payloads.

## Things that will bite you

- **PINs are strings.** Challenge pins start with a zero. `parsePin` in
  `lib/config.js` returns a string for this reason. Do not make it a number.
- **`title` contains HTML.** Kahoot puts `<b>` tags and entities in question
  text. Strip tags before decoding entities, or `&lt;b&gt;` turns into a tag
  and gets eaten. `stripHtml` in `lib/question.js` has the order right.
- **Answers match on text, never on index.** Kahoot shuffles options per
  player, and models reply in every format imaginable. See `lib/resolver.js`.
- **The challenge `correct` flag is a shortcut, not the normal path.** Live
  games never send it.
- **`answer()` hangs if the socket is closed.** It rejects after 10 seconds
  when the server does not answer, but it never settles at all when the
  socket is not open. Do not await it without a guard.
- **Do not await `client.answer()` in a hot path.** With many bots the
  receipts are slow to come back.

## Testing

```bash
npm test                  # unit and command tests, no network
npm run test:integration  # joins a real challenge and answers it
npm run test:scale        # 150 bots
```

The live tests use the public challenge PIN `00112233`. Override it with
`CHALLENGE_PIN`. The scale test honours `SCALE_BOTS` and `SCALE_PARALLEL`.

## Housekeeping

- The machine's `~/.zshenv` sets `NODE_TLS_REJECT_UNAUTHORIZED=0`, which turns
  off TLS certificate checking for every Node process. Not a problem in tests,
  but it means the resolver's API key travels unverified.
